# Branch coverage limitations (phosphor-host-postd)

This document records branch coverage after UT-only improvements and documents branches that cannot be covered without production changes or are impractical to cover in unit tests.

**Data source:** All branch counts and percentages below are from the gcovr HTML report under `build/meson-logs/coveragereport` (e.g. open `index.html` and drill into directory/file pages for the Branches column). Figures reflect the report in that directory (e.g. gcovr 8.6). To regenerate: run tests with coverage (`ninja -C build test && ninja -C build coverage-gcovr` with `-Db_coverage=true`), or use Docker CI per README. For text summary from repo root: `gcovr -r . --config gcovr.cfg --txt`.

**Scope:** Files under `lpcsnoop/`, `queued-boot-progress/`, and `sbmrbootprogress/` per `gcovr.cfg` (ipmisnoop is excluded from coverage). Excluded: `main.cpp`, `BootProgressMain.cpp`, `I2CPollingDevice.cpp`, `USBPollingDevice.cpp`.

## Overall coverage summary (from `build/meson-logs/coveragereport/index.html`)

| Metric | Covered | Total | % |
|--------|---------|-------|---|
| Lines | 474 | 606 | 78.2% |
| Functions | 67 | 76 | 88.2% |
| Branches | 268 | 482 | 55.6% |
| Decisions | 115 | 141 | 81.6% |

Branch coverage ceiling with UT-only improvements is estimated at ~60–62% (adding ~4 branches in `BootProgressPublisher.cpp` and ~1 in `CakBootProgressPublisher.cpp`). The remaining ~38% gap is attributable to compiler-generated arcs, D-Bus/hardware dependencies, and unreachable defensive checks documented per-file below.
